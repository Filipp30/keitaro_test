# Keitaro wrapper — тестовое задание Adrobot

Обёртка над [Keitaro Admin API](https://admin-api.docs.keitaro.io) из двух частей:

1. **Создаватор кампаний.** На вход — название, гео-код страны и ID оффера. Создаёт кампанию
   с настроенными доменом, группой и источником и двумя потоками:
   - **Поток 1** — фильтр `country = <гео>`, редирект (HTTP 302) на `https://www.google.com`;
   - **Поток 2** — весь остальной трафик уходит на выбранный оффер (доля 100%).
2. **Редактор существующей кампании.** Добавление и удаление офферов в потоке, ручная правка
   долей, кнопка «Распределить поровну». Доли всегда в сумме дают 100%.

Стек: **FastAPI + SQLAlchemy 2 + Alembic**, httpx для Keitaro API. Фронт — одна HTML-страница
на чистом JS (`app/static`), её отдаёт тот же FastAPI.

## Запуск

Нужен Python 3.11+ (проверено на 3.14).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # и вписать KEITARO_API_KEY
alembic upgrade head          # миграции: создаёт app.db (SQLite)
uvicorn app.main:app --reload # http://localhost:8000
```

API-ключ: админка Keitaro → Профиль → «API ключи» → «Создать новый ключ».
Swagger самой обёртки: http://localhost:8000/docs

### Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `KEITARO_URL` | `https://tlgk.host` | Адрес Keitaro |
| `KEITARO_API_KEY` | — | Ключ Admin API |
| `DATABASE_URL` | `sqlite:///./app.db` | Любой URL SQLAlchemy (например, PostgreSQL) |
| `GEO_REDIRECT_URL` | `https://www.google.com` | Куда редиректит поток 1 |
| `DEFAULT_GROUP_ID` / `DEFAULT_DOMAIN_ID` / `DEFAULT_TRAFFIC_SOURCE_ID` | — | Значения, предвыбранные в форме |

### Миграции

```bash
alembic upgrade head                                   # применить
alembic revision --autogenerate -m "описание"          # новая миграция после правки app/models.py
alembic downgrade -1                                   # откатить последнюю
```

`migrations/env.py` берёт URL базы из настроек приложения, поэтому alembic и приложение
всегда смотрят в одну и ту же базу.

### Тесты

```bash
pytest
```

Тесты не ходят в настоящий Keitaro: API замокан через `respx`, база — SQLite в памяти.

## Как считаются доли

Keitaro хранит долю оффера целым числом и **не проверяет**, что сумма равна 100
(`PUT /streams/{id}` спокойно сохраняет 60%). Поэтому этот инвариант держит обёртка:

- **Добавление оффера** — доли делятся поровну между всеми офферами потока:
  2 → 50/50, 3 → 34/33/33.
- **Удаление оффера** — его доля распределяется между оставшимися **пропорционально** их
  текущим долям: 50/25/25 без последнего → 67/33. Если доли были равными, они остаются равными.
- **Ручная правка** — сохраняется, только если сумма ровно 100 (проверка и в UI, и на сервере).
- **«Распределить поровну»** — сбросить доли на равные.

Округление — методом наибольшего остатка, поэтому сумма всегда ровно 100. Логика —
в `app/shares.py`.

Каждое изменение пишется в таблицу `offer_changes` (было → стало) и показывается
в «Истории изменений» под кампанией.

## API обёртки

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/meta` | Группы, домены, источники и офферы для формы |
| `POST` | `/api/campaigns` | Создать кампанию с двумя потоками |
| `GET` | `/api/campaigns/created` | Кампании, созданные через обёртку (из локальной БД) |
| `GET` | `/api/campaigns?group_id=&search=` | Список кампаний Keitaro |
| `GET` | `/api/campaigns/{id}` | Кампания с потоками и офферами |
| `POST` | `/api/streams/{id}/offers` | Добавить оффер в поток |
| `DELETE` | `/api/streams/{id}/offers/{offer_id}` | Удалить оффер из потока |
| `PUT` | `/api/streams/{id}/offers` | Сохранить доли вручную (сумма = 100) |
| `POST` | `/api/streams/{id}/equalize` | Распределить доли поровну |
| `GET` | `/api/campaigns/{id}/history` | История изменений офферов |

## Структура

```
app/
  main.py       — роуты FastAPI
  services.py   — бизнес-логика: создание кампании, редактор офферов
  shares.py     — расчёт долей
  keitaro.py    — клиент Keitaro Admin API
  models.py     — модели SQLAlchemy (created_campaigns, offer_changes)
  schemas.py    — Pydantic-схемы
  config.py     — настройки из .env
  static/       — фронтенд (index.html, app.js, style.css)
migrations/     — Alembic
tests/          — pytest
```

## Детали реализации

- Если поток не создался, кампания удаляется, чтобы в Keitaro не оставалось полусобранных кампаний.
- Оффер проверяется до создания кампании: несуществующий ID → 422, в Keitaro ничего не создаётся.
- Каждый запрос к Keitaro занимает ~0,8 с, поэтому независимые запросы выполняются параллельно,
  а список офферов кэшируется на 60 секунд.
- Редактор работает только с потоками-офферами (`schema = landings`); потоки-редиректы
  показываются только для чтения.
- Ошибки Keitaro пробрасываются в UI как есть (4xx), недоступность Keitaro — как 502.
